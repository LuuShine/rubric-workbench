# Benchmark 与 Rubric 构建方法论

## 1. 核心原则

Benchmark、Rubric 和业务结果不是三套独立体系，而是一条完整的评测闭环：

```text
业务目标
→ 明确评测决策
→ 构建 Rubric
→ 构建 Benchmark
→ 执行评测
→ 使用真实结果验证
→ 回流 Bad Case 与版本迭代
```

- **Benchmark** 回答：在什么样本上公平地比较。
- **Rubric** 回答：按照什么标准稳定地判断。
- **后验指标** 回答：这套评测能否预测真实效果。

评测体系最终应当具备四项能力：可比较、可复现、可归因、可验证。

## 2. 明确评测决策

生成评测方案前，应先确定评测需要支持什么决策。

### 2.1 准入判断

判断结果是否达到最低可用标准，是否允许进入下一阶段或上线。

### 2.2 质量比较

区分多个可用结果之间的质量差异，用于模型选择、版本比较或方案排序。

### 2.3 问题归因

说明结果差在哪里、问题属于哪个环节，以及应该采取什么优化动作。

### 2.4 版本决策

判断新版本是否可以替代旧版本，关注核心指标收益与不可退化项。

### 2.5 业务验证

判断离线评测结果是否能够预测真实用户行为或业务效果。

不同决策目标不能混用同一套分数解释。准入问题需要硬门槛，质量比较需要具有区分度的连续评分，问题归因则要求维度能够映射到具体环节。

## 3. Rubric 构建方法

Rubric 应从评测目标反推，而不是直接让模型自由罗列维度。

### 3.1 三层质量结构

#### 基础可用性

用于检查正确性、安全性、完整性、格式约束、明显缺陷等基础要求。

基础层通常包含不可接受问题，适合设置为硬性门槛。

#### 任务或场景效果

用于判断结果是否真正完成用户目标，是否符合特定任务、用户或使用场景。

这一层应体现任务差异，不能只使用通用的“质量好”“表达清晰”等描述。

#### 主观质量与相对偏好

用于衡量表现力、自然度、美感、吸引力、风格一致性等相对质量。

主观层适合用于可用结果之间的排序，不宜承担硬性准入职责。

三个层级应按任务需要选择，不应机械凑齐。

### 3.2 高低标双轨

#### 低标 Rubric

- 通常采用 `0/1` 或“通过/不通过”。
- 用于硬性准入和不可接受问题识别。
- 判断边界必须明确。
- 任一关键问题可以触发整体不通过。

#### 高标 Rubric

- 通常采用 `1-5`、MOS、GSB 或成对比较。
- 用于区分已经可用的结果。
- 需要清晰的质量梯度和锚点样例。
- 重点关注相对优劣，而不是重复基础准入判断。

#### 混合模式

先使用低标规则过滤不可用结果，再对通过基础门槛的结果进行高标评分。

硬性问题不能被其他维度的高分抵消。

### 3.3 维度设计要求

每个维度必须满足：

1. 只判断一个可观察属性。
2. 与其他维度保持互斥，避免重复扣分。
3. 能对应具体问题和优化动作。
4. 明确观察对象、判断边界和归因范围。
5. 直接关联任务目标。
6. 不使用无法落地判断的抽象质量词。

推荐使用以下形式定义维度：

```text
维度名称
→ 观察对象
→ 判断标准
→ 失败边界
→ 归因位置
→ 可执行建议
```

### 3.4 评分档位

连续评分至少需要建立三个锚点：

- **最低分锚点**：明显失败或不可接受。
- **中间分锚点**：基本可用，但存在明确缺陷。
- **最高分锚点**：完整满足要求，且不存在关键缺陷。

如果使用更细的分值范围，应描述相邻档位之间的差异。

评分说明必须包含可观察证据，不能只写“较差、一般、优秀”。

### 3.5 样例设计

每个维度应包含：

- 正向样例。
- 负向样例。
- 边界样例。
- 容易与其他维度混淆的反例。

样例必须对应具体任务，不能只是维度定义的同义改写。

### 3.6 权重设计

权重应综合以下因素确定：

- 评测目标。
- 错误风险。
- 用户影响。
- 问题发生频率。
- 对最终结果的影响程度。
- 与后验结果的相关性。

没有数据依据时可以采用先验均衡方案，但必须明确其为初始假设，不能伪造统计结论。

## 4. Benchmark 构建方法

### 4.1 三类评测集

#### 稳定回归集

- 输入和样本分布相对固定。
- 用于模型或版本之间的稳定比较。
- 保留长期锚点样本。
- 不因短期问题频繁修改。

#### 真实分布集

- 从真实请求、用户任务或生产流量中采样。
- 用于反映实际使用分布。
- 持续发现新场景和新问题。
- 应定期更新。

#### 专项挑战集

- 收录边界 Case、高风险 Case 和历史 Bad Case。
- 用于验证特定能力或修复效果。
- 可以随着问题发现持续扩充。
- 不能替代真实分布集。

三类集合用途不同，不应合并成一个无法解释的总集合。

### 4.2 分层抽样框

样本按照以下层级组织：

```text
使用场景
→ 类别
→ 子类别
→ 关键失败模式
→ 难度等级
```

每个样本都应记录所属层级，支持分组统计、问题定位和覆盖度分析。

### 4.3 难度设计

- **基础级**：验证基本能力和硬性要求。
- **常规级**：代表主要真实使用分布。
- **困难级**：包含复杂组合、歧义、长尾条件和多约束任务。
- **挑战级**：针对已知薄弱点和高风险问题。

高难度样本应能拉开模型或版本差异。如果所有系统都接近满分，评测集将失去区分度。

### 4.4 样本配比

样本比例需要根据以下信息确定：

- 真实流量分布。
- 业务风险。
- 历史错误频率。
- 当前优化重点。
- 评测成本。
- 所需统计置信度。

通用方案只能提供建议及其理由，不应在缺少数据时硬编码固定比例。

### 4.5 控制变量

进行模型或版本对比时，应尽量保证：

- 使用相同输入。
- 固定可控的随机参数。
- 对随机生成系统进行多次采样。
- 保持推理参数一致。
- 保持前处理和后处理流程一致。
- 隐藏模型、版本和来源标识。
- 随机打乱候选顺序。
- 控制位置偏好和品牌偏好。

### 4.6 Benchmark 与 Rubric 映射

每类样本都应明确：

- 覆盖哪些 Rubric 维度。
- 主要检测什么失败模式。
- 问题应归因到哪个环节。
- 属于准入样本、比较样本还是诊断样本。
- 对应什么验收标准。

通过建立映射，可以避免评测只能输出总分，却无法指导优化。

## 5. 有效性验证

### 5.1 结构有效性

自动检查：

- 权重总和是否合理。
- 维度是否重复。
- 是否缺少正向或负向样例。
- 评分档位是否覆盖完整范围。
- 样例是否与任务相关。
- 维度与样本之间是否存在覆盖空洞。
- 同一个问题是否在多个维度重复计分。

### 5.2 标注可靠性

持续监控：

- 人人一致率。
- 人机一致率。
- 标注尺度漂移。
- Pointwise 与 Pairwise 结果一致性。
- 候选顺序交换后的判断稳定性。
- 不同标注人员之间的系统性偏差。

同一轮评测内应尽量冻结评分尺度。维度边界发生变化时，应重新校准或重新标注受影响样本。

### 5.3 裁判模型准入

模型裁判需要评估：

- 问题样本召回率。
- 正常样本误报率。
- 精确率与 F1。
- 不同候选顺序下的稳定性。
- 与专家判断的一致性。
- 高风险样本上的失误情况。
- 对不同模型或风格的系统性偏好。

具体阈值必须结合任务风险和历史数据确定。

### 5.4 外部有效性

当存在真实用户或业务数据时，应检查：

- Rubric 得分是否与真实结果同向。
- 高分样本是否具有更好的后验表现。
- 离线分数提升是否带来线上改善。
- 哪些维度真正具有预测能力。
- 是否出现离线提升、线上不变的过拟合。
- 不同人群、场景和时间段下关系是否稳定。

外部结果用于验证 Rubric，不应直接成为单条内容的评分项，除非该结果能够从待评对象本身被直接观察。

## 6. 评测准入与上线决策

推荐将上线条件拆成两类：

### 6.1 不可退化项

- 基础质量不能下降。
- 高风险问题不能增加。
- 关键场景不能出现明显退化。
- 稳定性与可用率不能下降到不可接受水平。

### 6.2 目标收益项

- 目标维度获得明确提升。
- 提升能够跨多个样本层级复现。
- 优势不依赖少数异常样本。
- 必要时通过统计方法验证差异。
- 在线结果不出现明显负向变化。

只有同时满足不可退化项和目标收益项，才进入下一阶段验证。

## 7. 版本治理

每个评测资产应记录：

- 版本号。
- 创建与更新时间。
- 样本来源。
- 样本分布。
- Rubric 版本。
- 模型与推理配置。
- 随机参数。
- 标注规范。
- 历史评测结果。
- 变更原因。
- 已知适用边界。

核心回归集只在以下情况更新：

- 输入条件已经不兼容。
- 真实使用分布发生明显变化。
- 评测集分数饱和，失去区分度。
- 出现必须长期监控的新风险。
- Rubric 定义发生实质变化。

应同时保留稳定锚点和隐藏测试集，避免系统针对公开样本过拟合。

## 8. 推荐执行流程

```text
1. 定义业务目标与评测决策
2. 梳理输入、输出、风险和用户场景
3. 生成候选质量维度
4. 合并重复维度并建立层级
5. 定义硬门槛与连续评分项
6. 编写评分锚点和正反例
7. 建立三类 Benchmark
8. 设计分层抽样与难度分布
9. 建立样本到 Rubric 的映射
10. 执行盲评或模型裁判
11. 检查一致性与区分度
12. 使用后验结果验证有效性
13. 回流 Bad Case
14. 版本化发布
```

## 9. 常见反模式

- 直接让模型自由生成维度，没有明确评测决策。
- 使用多个含义重叠的维度重复扣分。
- 评分档位只有形容词，没有可观察边界。
- Benchmark 只覆盖常规样本，没有边界和高风险样本。
- 使用一个集合同时承担回归、真实分布和专项诊断。
- 模型对比时输入、随机参数或候选顺序不一致。
- 只看平均总分，不检查分场景结果和失败归因。
- 只验证评分体系内部一致性，不验证真实效果。
- 为了提高离线分数频繁修改评测集。
- 在没有数据依据时声明固定比例、权重或准入阈值。

## 10. 最终目标

一套成熟的评测体系不只是生成一份完整文档，而是形成以下闭环：

```text
目标可解释
→ 样本有代表性和区分度
→ 评分标准可执行
→ 结果可以复现
→ 问题能够归因
→ 结论能够指导优化
→ 离线结果可以被真实结果验证
```
